# Website Maintenance

How to make everyday changes to https://marvis.web.app without breaking SEO, the contact policy, or the deploy pipeline.

**Golden rule:** content lives in `src/data/` — routes, sitemap, indexes, and cross-links derive from it. Change the data, run `bun run ci`, push to `main`. Docs-only pushes (`.md`, `docs/**`) do not trigger a deploy.

## 1. Add a service page

1. Create `src/data/services/<slug>.ts` following the `Service` type (`src/lib/types.ts`):
   - `slug`, `name`, `shortName`, `group` (one of `AI & Agent Development`, `Marketing & CRM Automation`, `Security & Reliability`), `icon`, `order`;
   - SEO fields: `seoTitle`, `metaDescription`, `eyebrow`, `h1` — these must be **unique** across the site;
   - body fields: `intro`, `benefits`, `useCases`, `process`, `integrations`, `technologies`, `faqs`;
   - cross-links: `relatedProjects` (project slugs), `relatedArticles` (article slugs);
   - `ctaHeading`, `ctaBody` for the contextual WhatsApp CTA.
2. Register it in `src/data/services/index.ts` — import the file and add it to the `SERVICES` array.
3. That's it. The route `/services/<slug>/` is generated by `src/app/services/[slug]/page.tsx` via `generateStaticParams`, the sitemap entry appears automatically, the header's services dropdown and all indexes pick it up from `SERVICES`.
4. Run `bun run ci` locally; push to `main`.

## 2. Add an article

1. Create `src/data/articles/<slug>.ts` following the `Article` type:
   - `title`, `seoTitle`, `metaDescription` (unique), `excerpt`, `date` (ISO `YYYY-MM-DD`), `readingMinutes`, `tag`;
   - `content` — the markdown body. Internal links use root-relative URLs like `/services/ai-automation/` (the validator resolves every internal link);
   - `relatedArticles`, `relatedServices` to wire the topic cluster.
2. Import it and add it to the `ARTICLES` array in `src/data/articles/index.ts` — ordering by date is automatic.
3. Route `/articles/<slug>/`, sitemap entry, and index listings are generated automatically.
4. `bun run ci`, push.

## 3. Add or update a project

Project facts live in one file: `src/data/projects.ts`.

- **Adding a project:** add an entry with the repo's **verified GitHub API facts** (`url`, `description`, `topics`, `language`, `stars`, `updated`), the `service` slug it proves, and curated copy (`tagline`, `summary`, `problem`, `approach`, `capabilities`) that **restates** those verified facts. Never invent adoption numbers, customers, or outcomes.
- **Updating stats:** refresh `stars`, `topics`, `language`, `updated` from the GitHub API (`https://api.github.com/repos/hamids-ai-automations/<repo>`), keeping curated copy in sync with the new facts. The current snapshot is frozen as of **2026-11-25** (98 public repos, 19 documented projects, 14 articles).
- Set `featured: true` for repos shown in prominent sections.
- `bun run ci`, push.

## 4. Update the WhatsApp number

The number lives in **one place**: `SITE.whatsapp` in `src/lib/site.ts` (`number`, `display`, `href`). Every CTA and the brief builder build their links from it via `whatsappLink()`.

> Exception: `scripts/validate.mjs` independently asserts that pages contain `wa.me/923167417135` — update the `WHATSAPP` constant there too, or validation will fail after a number change.

## 5. Regenerate the OG image / touch icon

The SVG templates are committed inside `scripts/generate-og.mjs`; the PNGs are gitignored build artifacts:

```bash
bun run og     # rasterizes the SVGs with sharp → public/og.png (1200×630)
               #                              → public/apple-touch-icon.png (180×180)
```

Edit the template strings in `scripts/generate-og.mjs`, run `bun run og`, review `public/og.png`, then push — CI regenerates the same assets during `bun run ci`. **Never commit the PNGs.**

## 6. Local development and checks

| Command | What it does |
| --- | --- |
| `bun install` | install dependencies from `bun.lock` |
| `bun run dev` | dev server at http://localhost:3000 (normal Next dev, no export) |
| `bun run lint` | ESLint |
| `bun run typecheck` | TypeScript |
| `bun run og` | regenerate OG/touch PNGs |
| `bun run build:export` | static export into `out/` (sets `NEXT_OUTPUT=export`) |
| `bun run validate` | post-build gate over `out/` (SEO, links, machine surfaces) |
| `bun run ci` | lint → typecheck → og → build:export → validate — **run before every push** |

## 7. Daily live-check

`live-check.yml` runs every day at **06:15 UTC (11:15 Pakistan time)** and probes 19 production endpoints (home, about, contact, services + 3 service pages, projects + 1 case page, articles + 1 article, privacy, terms, `sitemap.xml`, `robots.txt`, `llms.txt`, `404.html`), expecting HTTP 200 and a content marker on each. A failure opens a red run at https://github.com/hamids-ai-automations/marvis-portfolio/actions. It can also be triggered manually (workflow_dispatch).

## 8. Content rules (non-negotiable)

1. **No invented claims** — every project fact traces to `src/data/projects.ts` (curated from the GitHub API); no invented clients, testimonials, certifications, or metrics.
2. **WhatsApp only** — no email links, no phone-call CTAs, no contact forms, no other channels. `+92 316 7417135`.
3. **Exactly one H1 per page**, unique title/description/canonical per page — the validator enforces both.
4. Articles must be genuinely useful, original, and internally linked — no filler to inflate page count.

## 9. Monthly checklist

- [ ] Daily live-check runs green for the whole month (Actions → *Live site health check*).
- [ ] Spot-check 2–3 pages on mobile and desktop (theme toggle, mobile sheet menu, WhatsApp CTA).
- [ ] Review project stats freshness: is `src/data/projects.ts` still accurate vs. the GitHub API? Refresh if stars/topics/updates drifted.
- [ ] Check deploy runs for the month: no skipped validations, no failed live verifications.
- [ ] Review [NEXT_STEPS.md](NEXT_STEPS.md) — promote or close open items.
- [ ] Google Search Console (once set up): sitemap status, indexing coverage, new queries.
- [ ] Confirm no secrets crept into the repo (`git log -p -- .github/` review) and that `public/og.png` / `public/apple-touch-icon.png` remain untracked.
