# Project Audit — Pre-Revamp Assessment

**Date:** 2026-11-25
**Scope:** Full audit of `hamids-ai-automations/marvis-portfolio` before the Next.js 16 rebuild.
**Auditor conclusion:** Rebuild the presentation and tooling layer; preserve the URL structure, the data honesty rules, and the WhatsApp-only contact policy.

---

## 1. Previous architecture

The site was generated by a **zero-dependency custom Node static-site generator**:

- Node 20, ES modules, **zero npm packages**, no runtime framework.
- `src/build.js` rendered **38 routes** into `dist/` from a committed snapshot of a GitHub "master record" (`data/master-record.json`, ~1.3 MB) plus hand-written content in `src/content/`.
- One hand-written stylesheet (`src/styles.css`, single ~38 KB CSS file) implemented the entire charcoal-and-gold design system.
- A daily `sync-master-record.yml` workflow refreshed the snapshot and redeployed when its hash changed.
- A dependency-free validator (`scripts/validate.js`) gated links, SEO basics, and contact policy before deploy.
- Per-page metadata, sitemap, robots, and JSON-LD were produced by hand-rolled string templating in `src/lib/seo.js`.

## 2. What was good (and was preserved)

| Strength | Why it mattered | What happened to it |
| --- | --- | --- |
| Zero dependencies | No supply chain, no updates, ~150 ms builds | Replaced by a standard stack; the *validator* kept the zero-dependency property |
| Content worked without JavaScript | Every page was usable with JS disabled | Kept: all content is server-rendered; JS only enhances (theme, reveals, menus, brief builder) |
| Honest data rules | Project claims traced to the master record; no invented clients, testimonials, or metrics | Kept verbatim — now traced to curated in-repo data (`src/data/`) |
| WhatsApp-only contact policy | One channel, no forms, no stored data | Kept; enforced by CSP `form-action 'none'` and the validator |
| URL structure and 301 hygiene | Existing rankings and backlinks | Kept 1:1 — every old URL resolves, all 36 legacy 301 redirects preserved in `firebase.json` |
| Validator gate | Broken builds never reached production | Rebuilt as `scripts/validate.mjs` (still dependency-free) and wired into CI |

## 3. What was weak

1. **Design ceiling.** A single hand-maintained CSS file could not express the premium visual hierarchy the site needed: no component system, no design tokens, no dark/light theming, very limited animation (script-applied scroll reveals only).
2. **No framework metadata.** Titles, descriptions, canonicals, OG/Twitter tags, and JSON-LD were string templates — correct but brittle, and every new page re-implemented them by hand.
3. **Single 38 KB CSS file** shipped to every page, with no per-page code splitting and no dead-CSS elimination.
4. **Stale self-documentation.** The README under-reported the site (4 → 10 articles over its lifetime), a symptom of docs maintained separately from the code that generated the pages.
5. **Data flow coupling.** The 1.3 MB master-record snapshot and the daily sync/redeploy workflow made every content fix ride on an external data refresh, and made the repo heavier than the site it produced.
6. **No interactivity.** No dropdown navigation, no mobile sheet menu, no theme toggle, no interactive contact aid — all impossible without a component framework.
7. **No type safety.** Content shape errors surfaced only at render time.

## 4. Decisions taken

| # | Decision | Rationale |
| --- | --- | --- |
| 1 | Rebuild on **Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + shadcn/ui**, static export | Metadata API, typed content model, component system, static hosting unchanged |
| 2 | **Preserve every existing URL**; keep all legacy 301 redirects | Zero SEO regression risk |
| 3 | Keep the **WhatsApp-only** policy (no forms, no email, no phone CTAs) | Owner's standing rule; enforced in CI |
| 4 | Replace the master-record sync flow with **curated in-repo data** (`src/data/`), facts frozen **2026-11-25** from the GitHub API | Removes external coupling; keeps every claim traceable; the sync workflow and 1.3 MB snapshot were deleted |
| 5 | Keep a **dependency-free validation gate** (`scripts/validate.mjs`) that gates deploy | The best idea of the old architecture, retained |
| 6 | Generate OG/touch-icon rasters at build time from a committed SVG template | Reproducible assets, no binaries in git |
| 7 | Single deploy pipeline `firebase-deploy.yml` with Workload Identity Federation (preferred) or a service-account secret | Modern auth, no credentials in source |
| 8 | Dark-first emerald-on-charcoal theme, Space Grotesk / Inter / JetBrains Mono self-hosted via `next/font` | The premium look the brief asked for, without external font requests |

## 6. What was deliberately **not** changed

- **URLs and redirects** — every existing URL still resolves; all 36 legacy 301 rules remain in `firebase.json`.
- **Contact policy** — WhatsApp `+92 316 7417135` remains the only contact channel.
- **Data honesty rules** — no invented clients, testimonials, certifications, or metrics.
- **Hosting** — Firebase Hosting site `marvis`, project `my-1st-web-app-ef52d` (Spark plan, static hosting only, no Cloud Functions).
- **Repo** — same repository, default branch `main`.

## 7. Legacy files removed

- Custom generator `src/` (`build.js`, `styles.css`, `pages/`, `content/`, `lib/`, `templates/`, `assets/`)
- Legacy scripts (`sync-data`, `build`, `validate`, `serve`, `test`)
- `tests/` (node:test suites)
- `data/master-record.json` (1.3 MB snapshot)
- Old workflows: `deploy.yml`, `ci.yml`, `sync-master-record.yml`, `live-check.yml` (replaced by `firebase-deploy.yml`, `ci.yml`, `live-check.yml`)

Preserved: `.firebaserc`, `firebase.json` (public dir updated `dist` → `out`; redirects untouched), `.gitattributes`, and the full URL structure.
