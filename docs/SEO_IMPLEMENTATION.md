# SEO Implementation

Everything implemented for search engines and answer engines on https://marvis.web.app, and how each item is enforced. Keyword targeting itself is documented separately in [SEO_KEYWORD_MAP.md](SEO_KEYWORD_MAP.md).

## 1. Per-page metadata

All page metadata is produced by the Next.js Metadata API through `buildMetadata()` in `src/lib/seo.ts`, so every indexable page emits, without exception:

| Element | Value |
| --- | --- |
| `<title>` | unique per page (validated for uniqueness and length) |
| `<meta name="description">` | unique per page, ≥ 50 chars (validated) |
| `<link rel="canonical">` | absolute `https://marvis.web.app…` URL (validated) |
| Open Graph | `og:title`, `og:description`, `og:url`, `og:image` (1200×630), `og:site_name`, `og:locale` (en), `og:type` (`website` / `article`) |
| Twitter card | `summary_large_image` + title, description, image |
| Article pages | additionally `article:published_time` (from the article date, UTC+5) |
| robots | index/follow by default; `max-image-preview: large`, `max-snippet: -1` sitewide |
| Icons | `favicon.svg` + `favicon.ico` + generated `apple-touch-icon.png`; `manifest.webmanifest` |

The shared OG image (`/og.png`) is generated at build time from a committed SVG template by `scripts/generate-og.mjs` (sharp rasterizes it to 1200×630, plus a 180×180 touch icon). PNGs are gitignored and regenerated in CI and locally.

## 2. Structured data (JSON-LD)

| Schema type | Used on |
| --- | --- |
| `Person` | home (`/`) — name, role, location, WhatsApp, GitHub profile |
| `WebSite` | home (`/`) |
| `ProfilePage` | `/about/` |
| `ContactPage` | `/contact/` |
| `Service` | each of the 10 `/services/<slug>/` pages |
| `SoftwareSourceCode` | each of the 19 `/projects/<slug>/` pages |
| `BlogPosting` | each of the 14 `/articles/<slug>/` pages |
| `BreadcrumbList` | every section and detail page (mirrors the visible breadcrumbs) |
| `FAQPage` | pages that render an FAQ block (service pages, home) |

All JSON-LD is emitted through the shared `JsonLd` component (`src/components/site/json-ld.tsx`) and contains **only verified facts** — no fabricated ratings, reviews, or aggregate business data.

## 3. Crawl surface

- **`sitemap.xml`** — generated by `src/app/sitemap.ts` from the same data modules that render the pages: home, indexes, all service, project, and article pages, plus the legal pages, with per-section `priority`/`changeFrequency` and real `lastModified` dates (repo `updated` dates, article dates).
- **`robots.txt`** — generated by `src/app/robots.ts`: allow all crawlers, declare the sitemap URL and host.
- **`llms.txt`** — committed at `public/llms.txt`: a markdown summary of the site for AI crawlers and answer engines (identity, services, projects, articles, contact).
- **`manifest.webmanifest`** — generated by `src/app/manifest.ts` (PWA metadata).
- **Custom 404** — `src/app/not-found.tsx` renders the branded not-found page; CI copies `out/404/index.html` to `out/404.html`, which Firebase Hosting serves as the not-found page.
- `trailingSlash: true` + Firebase `cleanUrls` — one canonical URL form per page (`/services/ai-automation/`), no `.html` extensions.

## 4. Breadcrumbs and heading hierarchy

- **Visible breadcrumbs** (`src/components/site/breadcrumbs.tsx`) on every detail page: Home → Section → Page, linked with descriptive anchor text and mirrored 1:1 by `BreadcrumbList` JSON-LD.
- **Headings:** exactly one `<h1>` per page (stated as the page's main topic); section headings are `<h2>`, sub-items `<h3>`. Enforced by the validator — the build fails if any page has 0 or 2+ H1s.
- **Semantic HTML:** `header`, `nav`, `main`, `article`, `section`, `footer`; one `main` landmark per page; navigation is crawlable plain anchors (including the services dropdown, which renders real links).
- **Image alt policy:** every meaningful image (the OG/Twitter card definitions, project/branding imagery) carries descriptive alt text built from the person's name and role or the asset's content; decorative icons are inline SVG/lucide icons that carry no content and are not advertised to assistive tech.

## 5. Internal linking

- Service ↔ project (`relatedProjects`), service ↔ article (`relatedArticles`), article ↔ article (`relatedArticles` on articles), plus "related" sections on detail pages — see [SEO_KEYWORD_MAP.md](SEO_KEYWORD_MAP.md) §6.
- Every internal link was checked by the validation gate: a broken internal link fails the build (see §7).
- All 36 legacy 301 redirects (§6) keep inbound links working.

## 7. Validation gate

`scripts/validate.mjs` (dependency-free Node) runs against the built `out/` directory in CI **before** deploy, and exits 1 on failure:

- unique, non-empty `<title>` and meta description per page;
- canonical URL present and absolute;
- exactly one `<h1>` per page;
- Open Graph title/description/image present;
- WhatsApp CTA (`wa.me/923167417135`) present on every page;
- `sitemap.xml`, `robots.txt`, `404.html`, `manifest.webmanifest`, `og.png`, `llms.txt`, `favicon.svg` exist;
- every internal `href` resolves to a file in `out/`;
- every sitemap URL resolves to a generated page.

A failing check means the build never deploys. This is the mechanism that keeps the items above true over time — SEO is enforced by the pipeline, not by review.

## 8. Performance (SEO-adjacent)

- **Fully static** — every page is pre-rendered HTML (`NEXT_OUTPUT=export`); no client-side data fetching.
- **Fonts self-hosted** via `next/font` with `font-display: swap` — no external font requests, no FOIT.
- **~zero CLS** — static layout, no dynamic content injection, dimensions known at render time.
- **Images unoptimized but static** — served from Firebase Hosting's CDN with the standard asset cache headers (7 days).
- HTML/XML/TXT/JSON responses use `must-revalidate`, so content changes propagate immediately on deploy.

## 9. Not integrated (documented blockers)

- **Google Analytics 4 / Google Tag Manager** — NOT integrated: no credentials were available. The current CSP (`script-src 'self' 'unsafe-inline'; connect-src 'self'`) blocks external analytics scripts; adding GA4 later requires a deliberate CSP change and a privacy decision.
- **Google Search Console** — sitemap submission pending owner authentication (see [NEXT_STEPS.md](NEXT_STEPS.md)).
- No per-page OG images yet — all pages share the generated `/og.png` card (per-page images are a ranked next step).
